# AVC / HEVC / AV1 Main Profile：块划分、帧内预测与残差编码详细对比

## 1. 比较范围与阅读方式

比较对象：

| 标准 | 本文限定的 Profile | 位深与采样范围 |
|---|---|---|
| AVC / H.264 | Main，profile_idc = 77 | 8 bit，4:2:0 |
| HEVC / H.265 | Main | 8 bit，4:2:0 |
| AV1 | Main，seq_profile = 0 | 8 / 10 bit，4:2:0，也支持单色 |

为便于同条件比较，正文默认使用 **8 bit、4:2:0、普通有损帧内编码**；特殊工具、无损路径和帧间编码差异另行注明。HEVC Main10、RExt、SCC，AVC High，以及 VVC 不计入本文的 Main 工具集合。

“Main”是各标准内部的 Profile 名称，不能认为它们允许的位深和工具相同。特别是：

- AVC Main **没有亮度 Intra_8×8，也没有 8×8 残差空间变换**。
- HEVC Main 没有 SCC 的 Palette / Intra Block Copy，也没有 RExt 的跨分量预测工具。
- AV1 Main 本身就包括 CfL、Filter Intra 和受条件控制的屏幕内容工具。

本文重点比较以下链条，而不只比较预测方向个数：

```text
编码块划分
  → 模式与角度选择
  → 变换尺寸选择及参考样本准备
  → 生成预测值 P
  → 计算残差 R = X - P
  → 变换、量化、系数编码
  → 反量化、逆变换、重建
  → 为后续块提供已重建参考
```

编码器可以改变搜索顺序，但必须生成符合规范的码流和重建结果。下面的计算式用于解释，实际实现还包含规范规定的整数缩放、舍入、裁剪与边界处理。

## 2. 先区分三种“块”

| 概念 | 回答的问题 | 不能混淆的地方 |
|---|---|---|
| 编码块 / 模式归属区域 | 哪一片区域共享帧内模式等语法？ | 不一定等于一次预测计算的区域 |
| 预测处理块 | 本次参考边准备和预测计算覆盖多少样本？ | 帧内计算经常按变换块逐块进行 |
| 变换块 | 哪一片残差共同进行二维变换？ | 不一定等于编码块；尺寸不一定为正方形 |

例如，HEVC 可以有一个 64×64 的帧内 PU，统一传一个亮度模式，但不执行 64×64 残差变换。它必须分成不超过 32×32 的 TU，逐 TU 做参考准备、预测和重建。

AV1 也可以有 128×128 的编码块，但最大空间变换为 64×64；普通帧内预测按变换块执行，不能把 128×128 编码块理解成一次 128×128 方向外推。

因此，“HEVC 最大帧内块是 32×32”与“HEVC 最大帧内块是 64×64”都需要说明所指层级：前者可以指实际预测／变换处理块，后者可以指模式所属 PU。

参考：[HEVC 逐 TU 重建实现](https://raw.githubusercontent.com/listenlink/HM/master/source/Lib/TLibDecoder/TDecCu.cpp)、[AV1 逐变换块预测与重建实现](https://aomedia.googlesource.com/aom/+/refs/heads/main/av1/decoder/decodeframe.c)。

## 3. 总体结构对比

| 项目 | AVC Main | HEVC Main | AV1 Main |
|---|---|---|---|
| 顶层局部编码单元 | 16×16 亮度宏块 MB | CTU，最大 64×64 亮度 | Superblock，64×64 或 128×128 亮度 |
| 编码区域划分 | 固定宏块，选择 Intra_4×4 / Intra_16×16 等类型 | CU 四叉树 | 以递归方形分裂为骨架，加水平／垂直／T 形／四条带等叶节点划分 |
| 最小亮度编码块 | 宏块固定 16×16；内部可为 4×4 预测区域 | 最小 CU 可配置到 8×8，内部最小 PU 可为 4×4 | 可到 4×4 编码块 |
| 帧内模式归属 | 每个 4×4，或整个 16×16 宏块 | 每个 PU；最小 CU 可选择四个 NxN PU | 每个划分后的编码块 |
| 普通帧内预测处理 | 4×4，或 16×16 预测 | 按 TU 处理，常规亮度为 4×4～32×32 | 按变换块处理，支持矩形，最大 64×64 |
| 常规空间变换尺寸 | 4×4 | 4×4、8×8、16×16、32×32 | 19 种方形／矩形尺寸，最大 64×64 |
| 编码块内变换尺寸分布 | 固定 4×4 网格 | 残差四叉树可产生混合尺寸叶 TU | 普通 Intra 在同一亮度编码块内使用统一变换尺寸；Inter 另有可变尺寸变换树 |
| 变换核选择 | 固定 4×4 整数变换，另有 DC 二级变换 | 常规 DCT-II；4×4 亮度 Intra 使用 DST-VII | 普通亮度 Intra 按尺寸使用 DCT / ADST / Identity 组合子集 |

## 4. 编码块划分：从固定宏块到多形状叶节点

### 4.1 AVC Main：固定 16×16 宏块

4:2:0 下，一个宏块覆盖 16×16 亮度和各 8×8 的 Cb、Cr。

亮度普通帧内选择主要是：

```text
一个 16×16 宏块
├─ Intra_16×16：整个宏块共用一个亮度模式
└─ Intra_4×4 ：16 个 4×4，各自选择亮度模式
```

不能因为 AVC 帧间支持 16×8、8×16、8×4 等分区，就认为 AVC Main 帧内也具有这些矩形预测模式。Intra_8×8 是其他 Profile 的扩展，不属于此处的 Main。

工程含义：在一片大平坦区域，即使相邻宏块都选同一种预测模式，仍需按宏块描述，不能合并成一个 64×64 模式区域；在宏块内需要更细方向时，可以使用 Intra_4×4。

### 4.2 HEVC Main：CTU → CU → PU / TU

CTU 的亮度 CTB 尺寸可为 16、32、64；CU 按四叉树递归划分。若配置最大 64、最小 8，则可能出现：

```text
64×64 CU
  └─ 分裂为四个 32×32 CU
       └─ 某个 CU 再分裂为四个 16×16 CU
            └─ 某个 CU 再分裂为四个 8×8 CU
```

每个帧内 CU：

- 通常采用一个 `2Nx2N` PU，整个 CU 共享亮度模式。
- 到 SPS 配置的最小 CU 层级时，还可以采用 `NxN`，产生四个正方形 PU。
- 例如最小 CU 为 8×8 时，`NxN` 可以得到四个 4×4 PU。

**Main 的帧内 PU 不使用帧间的 2NxN、Nx2N、AMP 非对称矩形分区。** CU 树和帧内 PU 的几何形状仍以正方形为主。

PU 解决模式归属；TU 解决残差组织。一个 PU 下可以存在多个 TU，并在 TU 之间复用同一模式。

参考：[HM 变换树及 NxN 约束](https://raw.githubusercontent.com/listenlink/HM/master/source/Lib/TLibDecoder/TDecEntropy.cpp)。

### 4.3 AV1 Main：10 类分区，22 种编码块尺寸

Superblock 为 64×64 或 128×128。AV1 的分区类型有：

| 分区 | 几何结果 |
|---|---|
| NONE | 不划分 |
| HORZ | 上下两个等大矩形 |
| VERT | 左右两个等大矩形 |
| SPLIT | 四个正方形子节点，可继续递归 |
| HORZ_A | 上半部分再左右分开，下半部分保留矩形 |
| HORZ_B | 上半部分保留矩形，下半部分再左右分开 |
| VERT_A | 左半部分再上下分开，右半部分保留矩形 |
| VERT_B | 左半部分保留矩形，右半部分再上下分开 |
| HORZ_4 | 四个水平条带 |
| VERT_4 | 四个垂直条带 |

示意：

```text
NONE         HORZ         VERT         SPLIT        HORZ_A
+-------+    +-------+    +---+---+    +---+---+    +---+---+
|       |    |       |    |   |   |    |   |   |    |   |   |
|       |    +-------+    |   |   |    +---+---+    +---+---+
|       |    |       |    |   |   |    |   |   |    |       |
+-------+    +-------+    +---+---+    +---+---+    +-------+
```

AV1 编码块尺寸集合为：

```text
正方形：4×4、8×8、16×16、32×32、64×64、128×128
比例 1:2 / 2:1：
  4×8、8×4、8×16、16×8、16×32、32×16、
  32×64、64×32、64×128、128×64
比例 1:4 / 4:1：
  4×16、16×4、8×32、32×8、16×64、64×16
```

注意三个限制：

1. 这些是枚举集合，不表示任意宽高组合都合法，例如没有 32×128 编码块。
2. 不是每个尺寸都能使用全部 10 种分区：8×8 的分区受限，4×4 不再分裂，128×128 不允许四条带分区；画面边缘也有推导约束。
3. AV1 主要通过 `SPLIT` 递归；其他分区产生叶编码块。不能把它当作“任意矩形都能继续二分”的 VVC QTMT。

矩形和 T 形叶节点让同一模式更贴合长边缘、文字笔画等区域，但是否节省码率仍取决于模式／分区语法开销和残差。

参考：[libaom 分区与尺寸定义](https://aomedia.googlesource.com/aom/+/refs/heads/main/av1/common/enums.h)。

## 5. 预测模式：方向密度与非方向模型都不同

### 5.1 模式数量应按块类型计算

| 亮度预测类型 | 方向与非方向模式 |
|---|---|
| AVC Main Intra_4×4 | 8 个方向 + DC，共 9 种 |
| AVC Main Intra_16×16 | Vertical、Horizontal、DC、Plane，共 4 种 |
| HEVC Main | 33 个 Angular + Planar + DC，共 35 种 |
| AV1 Main 基础模式 | 8 个 Directional + DC + Paeth + 3 个 Smooth，共 13 种 |
| AV1 Main 方向展开 | 支持角度偏移时，8×7 = 56 个方向；加 5 个非方向模式，常见计数为 61 个预测候选 |

AV1 的 Filter Intra、CfL、Palette、Intra Block Copy 另有适用范围，不能全部无条件加到每个亮度块的候选数上。

### 5.2 方向预测

**AVC Main** 为不同 Intra_4×4 方向规定具体的复制、二点平均或三点加权公式，没有通用的可微调角度语法。Intra_16×16 的方向选择较少。

**HEVC Main** 使用角度投影到主参考边。落在两个整数参考点之间时，通常按 1/32 位置权重做二点线性插值。负角度涉及从另一条参考边构造主参考的负索引扩展。33 个方向的斜率并非等角度间隔。

**AV1 Main** 使用基础方向加角度偏移：

```text
pAngle = baseAngle + 3 * angle_delta
angle_delta ∈ {-3,-2,-1,0,1,2,3}
```

8 个基础方向为 45°、67°、90°、113°、135°、157°、180°、203°。例如 90° 可扩展为 81°～99°，步长 3°。

角度偏移受编码块尺寸等语法条件限制；规范以 `MiSize >= BLOCK_8X8` 判断，不能简单用变换块边长是否达到 8 来代替。AV1 同样通过投影和二点加权生成方向预测，但前面还可能有参考边平滑或上采样，因此实际输入不同。

### 5.3 Plane、Planar 与 Smooth 不能直接画等号

| 模式 | 主要构造方式 | 特点 |
|---|---|---|
| AVC Plane | 从参考边估计水平／垂直梯度，构造平面 | 用于 Intra_16×16 和色度等指定类型 |
| HEVC Planar | 混合水平与垂直的线性变化 | 平滑二维过渡，与 AVC Plane 公式不同 |
| AV1 Smooth | 根据尺寸和位置查表，混合左右／上下方向的变化 | 使用预定义非均匀权重；另有 Smooth_H、Smooth_V |

这些模式都能描述平滑区域，但生成的预测值、边界条件与舍入规则不同。

### 5.4 Paeth 与 Filter Intra

Paeth 设左、上、左上参考为 `L,T,TL`，先构造 `p=L+T-TL`，再从 `L,T,TL` 中选择最接近 `p` 的样本值。它有利于保留某些边缘，而不是始终把多个值平均。

Filter Intra 有 5 个滤波模式，以小区域递归生成预测，之前生成的预测值可参与后续计算。它属于亮度预测工具；启用需要序列开关、DC 模式语法入口、没有亮度 Palette，且编码块宽高均不超过 32 等条件。

**Filter Intra 的内部预测递归不需要等每个小区域完成残差重建。** 这与相邻变换块之间使用“已重建像素”的依赖不同。

参考：[AV1 预测工具设计](https://arxiv.org/html/2008.06091v2#S5.SS2)、[AVC 预测实现](https://raw.githubusercontent.com/mirror/x264/master/common/predict.c)、[HEVC 预测实现](https://hevc.hhi.fraunhofer.de/HM-doc/_t_com_prediction_8cpp_source.html)。

## 6. 参考样本：平滑、扩展与可用性

详细核与选择条件见配套文档 [参考像素平滑对比]({{< relref "intra-reference-smoothing-main-profiles.md" >}})。这里只归纳与整个编码流程的关系。

| 项目 | AVC Main | HEVC Main | AV1 Main |
|---|---|---|---|
| 独立参考预平滑 | 无 | `[1,2,1]/4`，按 TU 尺寸／模式选择 | 0～3 档，按变换尺寸／方向／邻块 Smooth 模式选择 |
| 强平滑 | 无 | 32×32 亮度，通过线性检测后用端点插值 | 更强的局部 FIR，不是 HEVC 的整边端点插值 |
| 参考边上采样 | 无 | 无 | 特定小尺寸和角度下使用 `[-1,9,9,-1]/16` 插入半像素点 |
| 左上角处理 | 随具体预测公式 | 可参与参考三点滤波 | 部分方向和尺寸有独立角点滤波 |

共同点是：参考样本必须在规定解码顺序中已经可用。图像、Slice / Tile 边界、编码顺序和相应约束会改变可用性；不能把“内存中有这个像素”当作“规范允许引用”。

普通同帧帧内预测使用相应阶段的重建样本，而不是任意使用整帧环路滤波后的邻块样本。参考预滤波通常生成预测用副本，不把滤波值写回邻块重建图像。

AVC Intra_4×4 公式中的 `[1,2,1]` 加权属于预测生成，不能据此宣称 AVC Main 存在整条参考边的预平滑。

## 7. 变换划分：HEVC 的混合 TU 树与 AV1 Intra 的统一尺寸

### 7.1 AVC Main

- 普通空间残差按 4×4 变换。
- Intra_4×4 的预测与 4×4 残差处理较紧密对应。
- Intra_16×16 的预测覆盖整块，但残差仍分为 16 个 4×4，不做 16×16 DCT。
- Intra_16×16 的各 4×4 DC 系数还会集中进行二级变换，见下一节。

### 7.2 HEVC Main

TU 使用残差四叉树，亮度叶变换块为 4×4、8×8、16×16、32×32。树深和尺寸受 SPS、CU、PU 等约束。

一个 32×32 PU 可以共享一个模式，而 TU 采用：

```text
32×32 模式区域
├─ 左上 16×16 TU
├─ 右上 16×16 TU
├─ 左下 16×16 TU
└─ 右下再分成四个 8×8 TU
```

这是编码区域与残差局部统计之间的解耦：模式可以不变，局部变换尺寸可以变化。但普通帧内的预测会按这些 TU 重新取参考并生成，变换划分也会影响实际预测值。

### 7.3 AV1 Main 的普通 Intra

同一亮度编码块通过 `tx_depth` 选择统一的变换尺寸，随后用该尺寸铺满。普通 Intra 不能直接套用 HEVC 那样的混合尺寸叶 TU 树。

普通有损情况下，`tx_depth` 可编码范围至多为 0、1、2，实际可选数量还受块尺寸和帧级 `TxMode` 限制。例如：

| 编码块 | 典型可选的统一亮度变换尺寸 |
|---|---|
| 8×8 | 8×8、4×4 |
| 16×16 | 16×16、8×8、4×4 |
| 32×32 | 32×32、16×16、8×8 |
| 64×64 | 64×64、32×32、16×16 |
| 128×128 | 以最大 64×64 起步，可选 64×64、32×32、16×16 |

因此，不能声称“AV1 每个 64×64 帧内编码块都能直接选 4×4 变换”。需要更细空间适应时，可以进一步划分编码块；无损路径另有强制 4×4 规则。

矩形块沿规范的 `Split_Tx_Size` 表选择，不能假设每次宽高都同时减半。例如 16×8 可以依次得到 8×8、4×4，而不是一个未定义的任意尺寸。

**AV1 Inter** 有另外的递归可变尺寸变换树，深度也受限，可以形成混合尺寸。Intra Block Copy 走类帧间路径，应单独处理，不能混入这里的普通 Intra 规则。

参考：[AV1 规范 §5.11.15–17](https://aomediacodec.github.io/av1-spec/av1-spec.pdf#page=81)。规范的 `Max_Tx_Depth` 表表示达到 4×4 所需分裂次数，不等于 `tx_depth` 真能编码那么深；PDF 对此有明确说明。

## 8. 残差变换核：不能只比较“最大 4 / 32 / 64”

### 8.1 共同数学框架

对残差矩阵 `R`，可分离二维变换可以概念化为：

```text
C = T_vertical · R · transpose(T_horizontal)
```

选不同核，等于用不同空间基函数表示同一片残差。核是否合适取决于残差的相关性和边界特征，而残差又取决于分区、模式、参考处理与量化重建。

### 8.2 AVC Main：4×4 整数变换 + DC 二级变换

常规 4×4 变换是 DCT 近似的整数变换，缩放部分与量化／反量化结合，不是直接套浮点 DCT。

Intra_16×16 的亮度处理概念如下：

```text
16×16 预测残差
  → 16 个 4×4 整数变换
  → 各块 AC 系数分别编码
  → 取出每块 DC，组成 4×4 DC 矩阵
  → 对 DC 矩阵做 4×4 Hadamard 类二级变换
```

4:2:0 色度的每个 8×8 分量由四个 4×4 变换块组成，其四个 DC 还进行 2×2 Hadamard 类变换。

**4×4 DC 二级变换不等于对 16×16 像素残差直接做 16×16 空间变换。** AVC Main 也没有普通块级 DCT / ADST / Identity 的核选择。

参考：[x264 变换与 DC 变换实现](https://raw.githubusercontent.com/mirror/x264/master/common/dct.c)。

### 8.3 HEVC Main：DCT-II + 固定条件下的 4×4 DST-VII

| 变换情形 | 常规变换核 |
|---|---|
| 4×4 亮度 Intra | 整数 DST-VII，水平／垂直均使用 DST |
| 8×8、16×16、32×32 亮度 Intra | 整数 DCT-II |
| Main 的色度普通变换 | 整数 DCT-II，包含 4×4 色度 |

上述是非 Transform Skip、非 Transquant Bypass 的普通路径。4×4 亮度 DST 由条件推导，不是每块在 DCT 和 DST 之间传一个自由选择位。

DST 可以更好地描述某些帧内残差的一侧边界特性；这是核设计动机，不意味着所有帧内残差都应使用 DST。

HEVC 不沿用 AVC Intra_16×16 的亮度 DC Hadamard 二级变换：DC 和其他系数一起进入当前 TU 的系数编码。

参考：[HM 变换实现](https://raw.githubusercontent.com/listenlink/HM/master/source/Lib/TLibCommon/TComTrQuant.cpp)、[HEVC 4×4 DST 设计论文](https://ieeexplore.ieee.org/abstract/document/6522806)。

### 8.4 AV1：19 种变换尺寸

```text
正方形 5 种：
  4×4、8×8、16×16、32×32、64×64

比例 1:2 / 2:1 共 8 种：
  4×8、8×4、8×16、16×8、16×32、32×16、32×64、64×32

比例 1:4 / 4:1 共 6 种：
  4×16、16×4、8×32、32×8、16×64、64×16
```

19 种尺寸不意味着在每个编码块里都可以任意选择；还要符合当前块尺寸、统一变换铺设、分裂映射、位深和无损等约束。

矩形变换可以让长边方向保留较长的相关性，同时避免短边方向覆盖过多不相关区域。它和矩形编码块相互配合，但编码块与变换块的形状／大小仍不要求完全一致。

### 8.5 AV1 的 16 种全局类型与 Intra 子集

AV1 全局变换类型由 DCT、ADST、FLIPADST、Identity 等方向核组合构成，共定义 16 种二维类型。**普通帧内亮度并不使用全部 16 种。**

普通有损、具有非零残差、且语法允许选择时：

| 普通帧内亮度变换尺寸 / 控制 | 可用核集合 |
|---|---|
| 长边小于 32，且不是 16×16，`reduced_tx_set = 0` | 7 种：DCT_DCT、ADST_DCT、DCT_ADST、ADST_ADST、IDTX、V_DCT、H_DCT |
| 16×16，或上述小尺寸启用 `reduced_tx_set = 1` | 5 种：DCT_DCT、ADST_DCT、DCT_ADST、ADST_ADST、IDTX |
| 任一边达到 32 或 64 | DCT_DCT |

例如：

- 4×4、8×8、4×16、8×16 等，小尺寸可使用 7 种子集。
- 16×16 使用 5 种子集。
- 8×32、16×32、32×32、16×64、64×64 等普通帧内变换只用 DCT_DCT。
- FLIPADST 类类型存在于 AV1 全局工具集合中，但不属于这些普通 Intra 核集合。

命名中首个方向表示垂直核，例如 `ADST_DCT` 是垂直 ADST、水平 DCT。`V_DCT` 只在垂直方向使用 DCT，另一方向为 Identity；`H_DCT` 相反。

亮度的变换类型可按变换块选择，但同一编码块内的变换尺寸仍按前节统一。预测模式还会影响变换类型的熵编码上下文，因此“预测模式与变换类型相互独立”也不够准确。

**帧内色度**的变换类型通常由色度预测模式映射，再根据允许集合限制；不应照搬亮度每变换块的显式核选择规则。


### 8.6 AV1 的 64 点变换还有系数带宽限制

沿长度为 64 的变换轴，仅保留低频 32 个位置，高频部分置零：

| 空间变换尺寸 | 可编码的频域系数区域 |
|---|---|
| 64×64 | 低频 32×32 |
| 64×32 | 低频 32×32 |
| 32×64 | 低频 32×32 |
| 64×16 | 低频 32×16 |
| 16×64 | 低频 16×32 |

这不等于“实际做了一个 32×32 空间变换”：空间支撑和基函数仍对应原来的 64 点维度，只是不编码该轴的高频部分。

因此，大变换既可能节省语法和聚集低频能量，也可能不适合高频细节；编码器可以通过更小的变换或更细的编码分区避免不合适的大变换。


## 9. 预测与变换划分存在重建反馈

HEVC 和 AV1 普通帧内处理常见的依赖关系为：

```text
处理第一个 TU / 变换块：
  取已重建邻边 → 预测 P0 → 解码残差 R0 → 重建 X̂0
                                                      │
                                                      ▼
处理后续 TU / 变换块：
  可引用先前已重建的 X̂0 → 预测 P1 → 残差 → 重建
```

由此带来三个结果：

1. **改变变换划分，也可能改变预测值。** 更小变换块产生更多内部重建边界，后续预测可以使用更近的参考。
2. **量化也会影响后续块预测。** 后续块必须引用量化后重建值，编码器不能拿原始像素替代，否则编码器和解码器会漂移。
3. **同一模式的多个子块未必能完全并行。** 模式相同并不消除上／左重建依赖；可并行范围要按规范顺序和可用性分析。

AVC Intra_4×4 也有宏块内部的已重建子块依赖；Intra_16×16 则先生成整个宏块的预测，不能把内部 4×4 残差网格当成 16 个独立 Intra_4×4 预测区域。

这说明对帧内编码而言，`预测模式 → 残差 → 变换` 不是完全单向、互不影响的模块串联。编码器 RDO 需要考虑重建反馈。

## 10. 色度预测与亮度／色度块关联

### 10.1 AVC Main

4:2:0 下每宏块每个色度分量为 8×8，可使用 DC、水平、垂直、Plane。色度模式选择与亮度模式并不要求相同；同一色度模式用于相应的 Cb / Cr 预测。

色度通过自身的已重建参考边生成预测，不直接使用当前块亮度像素。

### 10.2 HEVC Main

常用候选包括 Planar、水平、垂直、DC，以及由亮度模式导出的 DM；候选重复时有相应替代规则。

**DM 复用的是亮度模式编号，不是把亮度像素线性变成色度像素。** 预测仍由色度参考样本生成。

4:2:0 下，亮度 TU 缩小时色度不一定按相同比例一直缩小：常规色度变换最小为 4×4，需要按规则与亮度子块关联。不能简单把每个 4×4 亮度 TU 映射为 2×2 色度变换。

### 10.3 AV1 Main 与 CfL

除普通色度帧内模式外，AV1 有 CfL（Chroma from Luma）：

```text
当前块已重建亮度
  → 按色度采样格式下采样
  → 减去均值，得到亮度 AC 变化
  → 乘以 U / V 各自的缩放参数
  → 加到对应色度 DC 预测上
```

概念公式：

```text
P_U = DC_U + alpha_U * (L_subsampled - mean(L_subsampled))
P_V = DC_V + alpha_V * (L_subsampled - mean(L_subsampled))
```

实际为定点运算并带舍入、裁剪；CfL 的可用性受块尺寸和无损等条件限制。

CfL 的优势是利用当前块亮度和色度的结构相关性；代价是明确的亮度重建到色度预测依赖。若只处理亮度 UT，无法覆盖这种跨分量路径。

AV1 的很小亮度块还涉及色度样本的归属与聚合，不能机械地把 4×4 亮度编码块理解成附带两个独立 2×2 色度预测／变换块。

## 11. 屏幕内容与特殊模式

| 工具 | AVC Main | HEVC Main | AV1 Main |
|---|---|---|---|
| Palette | 无 | 无；SCC 扩展另论 | 有，颜色表 + 像素索引 |
| Intra Block Copy | 无 | 无；SCC 扩展另论 | 有，从当前帧允许区域取已重建样本 |
| Filter Intra | 无 | 无同名工具 | 有，5 种递归预测滤波模式 |
| 原始 PCM 样本模式 | I_PCM | PCM，可选启用 | 无与上述完全相同的块级 PCM 语法 |

Palette 针对少量颜色的文字、图标、界面区域，每张表最多 8 个条目，受块尺寸和屏幕内容开关等约束。它不是“每像素只传索引且一定没有残差”，仍要按规范考虑对应残差路径。

Intra Block Copy 使用当前帧的块位移和受限参考区域，可以复用重复图案；它不属于上／左参考边外推。AV1 的 IBC 还影响残差处理路径及部分帧级工具的可用性，不能只增加一个预测函数就认为完整支持。

## 12. 量化、跳过变换与无损不能混为一谈

| 项目 | AVC Main | HEVC Main | AV1 Main |
|---|---|---|---|
| 常见量化参数 | 8 bit 亮度 QP 0～51 | Main 8 bit 亮度 QP 0～51 | 基础 qindex 0～255，结合分量／分段／局部偏移推导 |
| 常规变换跳过 / Identity | 无 HEVC 式 Transform Skip 或 AV1 式 IDTX | PPS 允许时可对 4×4 使用 Transform Skip | 合法变换集合内有 IDTX 和单方向变换 |
| QP / qindex 数值可直接横比 | 不可 | 不可 | 不可 |
| 无损相关路径 | Main 没有 High 系列的变换旁路工具；I_PCM 可直接编码样本 | 可选 Transquant Bypass；不等于 Transform Skip | 满足规范 Lossless 条件时，使用 4×4 可逆 WHT 路径 |

需要区分：

- **HEVC Transform Skip**：跳过空间核，但通常仍有规范缩放、量化和系数编码；不自动等于无损。
- **HEVC Transquant Bypass**：旁路变换和量化，是另一条控制路径。
- **AV1 IDTX**：Identity 类变换，不自动旁路量化，也不自动等于原始像素无损。
- **AV1 Lossless**：由量化索引及相关偏移等条件共同确定；不能只看到 `base_q_idx = 0` 就忽略分段和分量偏移。
- **没有非零残差**：表示重建等于预测；是否等于原始样本要看预测误差，不能与无损编码画等号。

AV1 无损时规范可能仍把类型变量标为 DCT_DCT，但逆变换根据 Lossless 标志走 WHT；不能只查看 `tx_type` 枚举就断定执行了 DCT。

## 13. 模式语法与残差熵编码

### 13.1 预测模式的信令

| 标准 | 典型方式 |
|---|---|
| AVC Main | Intra_4×4 利用上／左模式推导预测模式，编码命中标志或剩余模式；Intra_16×16 的模式与宏块类型相关联 |
| HEVC Main | 从邻块等构造 3 个 MPM，编码 MPM 命中／索引或剩余模式 |
| AV1 Main | 13 类基础模式使用上下文 CDF；方向偏移另编码；CfL、Filter Intra、Palette 等有各自语法 |

因此，“方向更多”也会改变信令成本；码率开销取决于概率模型、邻块上下文和实际模式分布，不是固定多传若干比特。

### 13.2 系数编码

| 标准 | 熵编码与系数组织 |
|---|---|
| AVC Main | 可使用 CAVLC 或 CABAC，由 PPS 等控制；分别处理 DC / AC 等残差类别 |
| HEVC Main | CABAC；包含末非零位置、系数组显著性、系数显著性、幅值／符号等，部分扫描选择与模式／尺寸相关 |
| AV1 Main | 基于 CDF 的多符号算术编码；对变换块全零、EOB、系数基础幅值、扩展幅值、符号等建立上下文，扫描与变换类别相关 |

AV1 的系数上下文还会区分二维变换和单方向变换。即使两个变换的非零系数数目相同，位置分布、扫描、幅值以及模式概率不同，也可能得到不同码率。

EOB 表示扫描中最后一个非零位置之后的边界，不应解释为“非零系数数量”。

参考：[AV1 系数解码实现](https://aomedia.googlesource.com/aom/+/refs/heads/main/av1/decoder/decodetxb.c)。

## 14. 用同一个 32×32 图像区域理解差异

### 情形 A：大面积平滑渐变

| 标准 | 可能的编码选择，非强制 |
|---|---|
| AVC Main | 4 个 16×16 宏块，各自选 Plane / DC 等；残差仍以 4×4 编码，Intra_16×16 另处理 DC |
| HEVC Main | 一个 32×32 CU / PU，选 Planar 或角度模式；可用一个 32×32 DCT TU |
| AV1 Main | 一个 32×32 编码块，选 Smooth / Directional 等；可用一个 32×32 DCT_DCT，或选更小统一变换 |

大块可能减少分区和模式语法开销，大变换可能聚集低频残差；但这些是内容相关的可能收益，不保证每次都优于小块。

### 情形 B：中间有一条狭长竖边

AVC Main 主要通过宏块内部 Intra_4×4 调整方向。HEVC Main 可通过 CU 四叉树细分，并调整局部 TU。AV1 可以把区域分成较窄的矩形叶块，各自选择方向／Paeth／Smooth，并使用相应矩形变换。

矩形有机会避免在同一编码块里混合边缘两侧的不同统计，从而降低残差；代价是更复杂的分区选择和语法。

### 情形 C：右下角局部纹理，其余平滑

HEVC 可以保持一个 PU 模式，在局部细分 TU，形成混合尺寸。AV1 普通 Intra 若只改变 `tx_depth`，会改变整个编码块的统一变换尺寸；要只细化局部区域，通常需要更改编码块分区。

这体现了一个重要区别：**AV1 在编码块几何形状和小块变换核上更丰富；HEVC 的普通帧内残差树在单个模式区域内允许混合 TU 尺寸。** 不能把所有维度都概括成“AV1 比 HEVC 更灵活”。

### 情形 D：文字、图标、重复 UI

AV1 可以考虑 Palette / IBC，而 AVC Main、HEVC Main 没有这些工具。在这种内容上，收益可能主要来自表示方式的改变，而不是方向从 33 个增加到 56 个。

## 15. 编码器搜索与实现成本

以下为根据上述规范结构作出的工程分析，不是标准规定的编码器算法。

候选的完整代价可概念化为：

```text
J = D(X, reconstructed_X)
    + lambda * (R_partition + R_mode + R_angle + R_tx_size
                + R_tx_type + R_coeff + R_other)
```

| 层面 | AVC Main | HEVC Main | AV1 Main |
|---|---|---|---|
| 几何搜索 | 宏块类型和内部小块模式 | CU 树、PU 模式、TU 树 | 更多叶分区形状、模式、角度和矩形变换 |
| 核搜索 | 基本无需普通核类型搜索 | 普通核由尺寸／分量条件推导，另有 Skip / Bypass | 亮度小变换需在合法核集合中选择 |
| 参考缓冲 | 少量 4×4 / 16×16 邻边 | 扩展参考、普通／强平滑缓冲 | 方向相关扩展、平滑、上采样、矩形索引 |
| 色度依赖 | 色度自身参考 | 色度自身参考 + DM 模式推导 | 增加 CfL 的亮度重建依赖 |
| 测试维度 | 模式、边界、DC / AC 类别 | CU / PU / TU 组合、树深、DST、参考平滑 | 分区形状、尺寸／核集合、角度、边滤波、CfL 和特殊工具组合 |

实际编码器通常进行多级剪枝：先用粗略代价筛候选，再对少量候选做量化重建和精细 RDO。不能用 `分区数 × 61 × 19 × 16` 直接估算 AV1 的合法搜索空间：大量组合受规则限制，普通 Intra 也不具备全部 16 种核。

评估实现速度时，应固定输入格式、分辨率、质量或码率目标、线程、工具开关和编码器速度档。不能只根据工具数量给出固定倍数的速度或压缩收益。

## 16. 容易误写的结论

| 不准确表述 | 更准确的表述 |
|---|---|
| AVC Main 有 Intra_8×8 参考滤波 | Main 没有；支持 Intra_8×8 的其他 Profile 才有 |
| AVC Intra_16×16 做 16×16 DCT | 残差仍做 4×4，亮度 DC 再做 4×4 二级变换 |
| HEVC 帧内最大块只能是 32×32 | 模式所属 PU 可到 64×64；普通预测／变换按最大 32×32 TU 执行 |
| AV1 Superblock 128，所以有 128×128 变换 | 最大空间变换为 64×64 |
| AV1 所有帧内块都有 56 个方向 | 角度偏移受编码块条件限制 |
| AV1 每个帧内变换都可以试 16 种核 | 普通帧内亮度是 7 / 5 种子集，大尺寸仅 DCT_DCT |
| AV1 普通 Intra 可以任意混合 TU 大小 | 同一亮度编码块使用统一变换尺寸；Inter 的变换树规则不同 |
| 换 TU 划分只改变变换，不影响预测 | 帧内逐 TU 重建会改变内部参考及后续预测 |
| HEVC DM 和 AV1 CfL 都是亮度预测色度 | DM 复用模式；CfL 利用当前块重建亮度像素 |
| AV1 Filter Intra 就是参考边滤波 | 两套独立工具，作用对象和递归方式不同 |
| HEVC Transform Skip / AV1 IDTX 就是无损 | 是否无损还取决于量化与专门的旁路／无损规则 |
| AV1 64×64 能编码完整 4096 个频域系数 | 可编码低频 32×32，64 点轴的高频部分置零 |
