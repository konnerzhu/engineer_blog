# DCT 详解：混合视频编码为什么使用余弦变换？

## 1. 先给结论

视频编码中的 DCT（Discrete Cosine Transform，离散余弦变换）把一个小块的**空间样本**重新表达为一组不同空间频率的**系数**。它本身不丢信息，也不直接压缩数据；编码器随后对系数量化、把许多不重要的小系数变成零，再用熵编码高效表示剩下的系数。

混合编码采用 DCT 类变换，核心原因是预测之后的残差通常仍有空间相关性：相邻残差往往相似。DCT 能把这类平滑、缓慢变化的残差较集中地表示在少量低频系数中。量化和熵编码因而有机会用较少比特表示它。DCT 还具有可分离、规则、可用整数近似实现等工程优点，适合按块处理和在不同硬件上确定性解码。

但 DCT 并非对所有内容、所有残差都最优。现代编码标准因此采用多种变换核、尺寸和旁路方式，让编码器按块选择更合适的表示。

## 2. DCT 做的事：换一套基底来描述样本

设一维残差块有 N 个样本 `x[n]`。正交归一化 DCT-II 可写为：

```text
X[k] = α(k) · Σ(n=0…N−1) x[n] · cos(π(2n+1)k / 2N)

α(0) = √(1/N)
α(k) = √(2/N),  k > 0
```

这里 `k` 是频率索引，`X[k]` 是对应余弦基函数的系数：

- `k = 0` 是 DC 分量，反映块内平均值或整体偏移。
- 较小的 `k` 表示样本在块内较缓慢的变化，也就是低频成分。
- 较大的 `k` 表示更快的变化，例如细纹理、锐利边缘或噪声，也就是高频成分。

把这些系数按相应余弦基函数加权相加，可以还原原来的样本。二维块的 DCT 可以先逐行做一维变换，再逐列做一维变换（或反过来）；这叫**可分离性**。因此，实现二维变换不必把每个输出系数都当成一整块样本的独立点积。

二维 DCT 的直观结果可以想成一张“频率地图”：左上角对应水平和垂直方向都变化缓慢的成分；向右表示水平方向变化更快，向下表示垂直方向变化更快。实际系数的排列、缩放和整数实现由具体标准规定。

## 3. 为什么平滑内容往往只需要少量系数

假设一个残差块的每个样本都等于常数 `c`。所有样本相同，没有任何块内变化：理想正交 DCT 中只有 DC 系数非零，所有 AC 系数为零。若残差是缓慢渐变，能量通常主要集中在 DC 和一些低频系数；若残差交替变化或包含细密纹理，较多高频系数会变得重要。

这种“把能量集中到少数系数”的性质称为能量聚集。它很适合后续的有损编码：编码器可以给不同频率系数分配不同精度。经过量化，幅值较小、视觉影响较低的系数可能归零；连续的零区和稀疏的非零系数也更容易由熵编码器表示。

这不是“DCT 自动把图像压缩”的意思。理想变换只是可逆地改写数据。节省比特主要发生在量化减少精度和非零系数数量之后，再由熵编码利用零游程、系数位置和幅值的统计规律。若残差能量分散在许多系数上，DCT 未必减少码率，变换系数甚至可能比原样本更难编码。

## 4. 它与 KLT 的关系：接近常见相关信号的好基底

从统计角度，针对已知信号协方差矩阵，Karhunen–Loève Transform（KLT）能够使变换系数互不相关，并在平方误差等条件下实现最佳能量聚集。但每种信号统计特性都可能需要不同的 KLT 基底，计算和信令成本也很高。

对常见的、相邻样本高度相关且统计特性随位置变化不大的信号，DCT 的余弦基底常能近似 KLT 的主要效果。DCT 的基底固定、可快速计算、无需传输一套数据相关的变换矩阵，所以成为实用的折中。

这里的“近似”有前提。真实视频残差可能受预测模式、运动补偿误差、遮挡、块边界、纹理和噪声影响，并不一定满足理想统计模型。某些强方向纹理或单侧边界的残差，用 DCT 表示并不经济；这也是标准增加其他变换选择的原因。

## 5. 为什么先预测，再对残差做 DCT

混合视频编码的基本路径是：

```text
原始当前块 X
    │
    ├─ 空间帧内预测，或使用参考帧做运动补偿
    ▼
预测块 P
    │
    └─ 残差 R = X − P
            │
            ├─ DCT 类变换：R → 系数 C
            ├─ 量化：C → 较稀疏的整数系数 Q
            └─ 熵编码：编码 Q 和必要的模式语法

解码器：熵解码 → 反量化 → 逆变换 → R̂ → P + R̂ 重建
```

直接变换原始像素时，平均亮度和大尺度结构也需要编码。预测先利用相邻块或已解码参考帧去掉可预测部分，让剩余残差通常更小、相关性更适合压缩。变换再把残差中的相关变化改写成频率系数，量化更容易在可控失真下删减信息。

预测和变换各解决一类冗余：预测主要消除块与块之间、帧与帧之间的可预测性；变换主要重新组织单个残差块内部的空间相关性；量化控制精度；熵编码利用最终语法和系数的概率规律。四者协作，构成“混合”编码的核心。

预测并不保证残差总是平滑。例如运动边界附近可能出现一侧为正、一侧为负的误差；参考帧不匹配可能形成细碎残差；帧内方向预测也可能留下特定方向的结构。因此，编码器通常把块划分、预测模式、变换尺寸、变换类型和量化强度一起做率失真优化。

## 6. DCT 的工程优势

### 6.1 正交基让变换和逆变换结构清楚

理想正交 DCT 的正向与逆向变换互为转置；未量化时可以恢复原输入（忽略有限精度实现误差）。这让“换基表示”和“有损量化”在概念上分开：变换负责组织信息，量化负责丢弃精度。

### 6.2 可分离，复杂度可控

二维变换可拆成两个一维变换。快速算法还能利用蝶形结构、对称性、常量乘法和移位，减少乘加运算。块尺寸通常较小，适合并行处理、流水线和专用硬件。

### 6.3 整数近似可以让解码重建一致

现代视频规范不会简单要求解码器运行不受限的浮点 DCT。AVC 使用 DCT 思路的整数变换；HEVC 规范定义定点整数变换；AV1 也规定整数逆变换过程。它们可通过整数加法、乘法、移位、舍入与剪裁获得可复现的重建结果，降低不同平台因浮点误差产生解码漂移的风险。

整数变换通常是对理想余弦变换的规范化近似，不意味着每个系数都等于教科书 DCT 的浮点数。编码器可以用更宽精度的方法搜索候选，但输出码流和解码器的反变换必须满足标准规定。

### 6.4 局部块处理适合视频的非平稳内容

整帧的统计性质很不一致：天空平滑，文字锐利，物体边缘有方向，背景可能是噪声。把整帧做一次全局变换会难以适应这些局部变化。按块变换允许编码器让不同区域选不同的块大小、变换核和量化强度；代价是需要编码划分与选择语法，也要处理块边界带来的影响。

## 7. 余弦变换的局限与常见失真

- **残差不够相关时，系数不会稀疏。** 随机噪声或剧烈变化可能分散到许多频率位置，无法获得理想的能量聚集。
- **硬边缘会带来宽频谱。** 阶跃或尖锐边缘不是少数低频余弦的组合；变换块与边缘不对齐时，能量可能扩散到许多系数。
- **量化会导致振铃和块效应。** 高频系数被粗量化后，边缘附近可能出现振荡；相邻块独立变换且重建误差不同时，边界可能显现。它们来自变换、量化和块处理共同作用，不应简单归结为“DCT 有损”。
- **变换语法也要付码率。** 更复杂的变换或更细的尺寸选择虽可能减少残差系数码率，却需要信令和编码器搜索成本，未必整体划算。
- **DCT 不是感知模型。** 频率高不必然代表视觉上不重要。细线、字幕、纹理和色度细节都可能显著；编码器的量化决策还要考虑失真度量和视觉权重。

编码器通常以率失真代价比较候选：

```text
J = D(X, X̂) + λ · R
```

其中 `D` 是原始块和重建块之间的失真，`R` 是模式、变换、量化和系数等语法所需比特，`λ` 控制码率与失真的权衡。因而，“DCT 更容易聚集能量”是重要优势，但最终是否采用 DCT，仍需看它相对其他候选能否降低整体代价。

## 8. AVC、HEVC、AV1 中的 DCT 并非完全相同

| 标准 | DCT 类工具的实际用法 | 对“编码器用了 DCT”的补充说明 |
|---|---|---|
| AVC / H.264 Main | 4×4 整数变换，常称近似 DCT；Intra_16×16 亮度和色度 DC 另有二级变换处理 | Main 的普通亮度路径不是对整块直接做任意尺寸的浮点 DCT；Profile 会限制可用工具 |
| HEVC / H.265 Main | 常规残差主要用整数 DCT-II；4×4 亮度帧内有 DST-VII 特例 | 变换树可适配不同残差区域；Transform Skip 在满足语法条件时可跳过常规变换 |
| AV1 Main | DCT 是核心候选之一，也定义 ADST、FLIPADST、Identity 等受限的水平／垂直组合 | 不是所有块都可以选所有变换；可用集合受帧内／帧间模式、尺寸和变换集约束 |

因此，更精确的说法是：**现代混合视频编码广泛使用 DCT 类整数变换，但标准通常不是只提供一种理想 DCT。** 具体核、尺寸、系数范围、缩放、舍入和可选条件均由标准定义。

## 9. 一句话串起整体逻辑

```text
预测去掉可预测结构
    → DCT 类变换重新组织块内残差
    → 量化以可控失真减少系数精度和数量
    → 熵编码压缩剩余符号
```

DCT 之所以长期适用于混合编码，是它在统计效率、可逆表示、整数实现、复杂度和硬件实现之间取得了很好的工程平衡；现代标准再用多种变换核、分块策略和旁路工具弥补它对特定残差形状的不适应。
