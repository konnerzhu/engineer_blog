# AV1、HEVC、AVC 参考帧管理详细对比

## 1. 先区分三件事

“参考帧管理”不是单一列表，而是三个相关环节：

1. **存储与输出**：解码图像何时保留在解码图像缓冲区（DPB / frame buffer），何时可以输出或释放。
2. **标记与刷新**：当前解码图像完成后，哪些缓冲区仍可供后续预测，哪些位置被新图像替换。
3. **当前图像引用选择**：当前图像可以引用哪些已保存图像，如何构造参考列表或参考槽映射。

运动估计是编码器选择运动向量的搜索过程；参考帧管理则确定可用的参考图像和缓冲状态。二者相关，但不是同一个工具。

## 2. 一眼看懂三种设计

```text
AVC / H.264
当前图像 ──参考列表 L0/L1──> DPB 中短期/长期参考图像
                 ↑
   滑动窗口或自适应 MMCO 管理标记和移除

HEVC / H.265
当前图像 ──RPS 决定本图可用集合──> DPB 中短期/长期参考图像
                         └─由 RPS 派生参考图像列表 L0/L1

AV1
当前图像 ──参考帧类型映射──> 8 个参考帧槽（LAST、GOLDEN 等）
   解码后按 refresh_frame_flags 将当前帧写入一个或多个槽
```

简要说：**AVC 以参考图像标记和参考列表管理为核心；HEVC 以每图声明的 RPS 管理存留集合；AV1 以固定数量的参考槽和逐帧刷新位图管理。**

### 图 1：参考图像的使用与更新

```text
已解码参考图像 ──按参考索引选择──▶ 当前块的预测 ──加残差──▶ 当前图像重建
       ▲                                                       │
       └──────── 解码完成后：保留、移除或刷新参考位置 ─────────┘

AVC：DPB + 滑动窗口 / MMCO
HEVC：DPB + 当前图像的 RPS
AV1 ：帧缓冲 + 8 个槽 + refresh_frame_flags
```

### 图 2：解码顺序不等于显示顺序

```text
显示顺序：  F0 ───── F1 ───── F2 ───── F3
解码顺序：  F0 ───── F3 ───── F1 ───── F2
                       ▲         ▲
                       └────┬────┘
                            F1 可引用较早显示、但已先解码的 F3
```

双向预测可以引用显示时间上“在未来”的图像，因为它在解码当前图像前已经解码并保存在缓冲中。参考是否可用要看解码顺序与管理状态，不能只按显示时间判断。

## 3. AVC / H.264：DPB、滑动窗口、MMCO 与参考列表

### 3.1 DPB 同时承担参考存储和输出重排序

解码图像可能需要暂存两种原因：等待显示输出，或供后续图像做帧间预测。DPB 负责跟踪图像的输出状态、短期／长期参考状态及移除。编码顺序与显示顺序可以不同，因此不能简单地按显示时间先后删除旧图像。

### 3.2 短期和长期参考图像

- **短期参考图像**通常用相对图像顺序（基于 `PicNum`）识别。
- **长期参考图像**使用长期索引（`LongTermPicNum` / `LongTermFrameIdx`）识别，适合编码器在普通滑动窗口之外继续保留某张图像。
- 参考图像数受 Level、序列参数和 DPB 容量限制；H.264 的语法与限制不能概括成“永远最多 N 张”，要结合码流配置看。

### 3.3 两种参考图像标记模式

1. **滑动窗口标记**：当短期参考图像占满可用参考容量时，按规则将最旧的短期参考图像标记为“不再用于参考”。这是较简单的 FIFO 式策略。
2. **自适应参考图像标记**：使用 `adaptive_ref_pic_marking_mode_flag` 和 MMCO（Memory Management Control Operation）语法，显式管理参考状态，例如移除短期／长期图像、将短期图像转为长期、设置长期索引，或清空参考标记。

IDR 图像提供强随机访问边界：它刷新旧参考状态，使后续解码不依赖 IDR 之前的参考图像。非 IDR 的普通 I 图像则不一定具有相同的参考刷新语义。

### 3.4 参考列表构造

- P slice 使用 **List 0**；B slice 可使用 **List 0 和 List 1**。
- 列表按规范规则从短期、长期参考图像排序构造；切片头可发送列表重排命令。
- 每个预测分区再选择列表中的参考索引，运动向量相对于所选图像解释。

### AVC 参考关系示意

```text
DPB： [短期 I0] [短期 P3] [短期 P1] [长期图像 L0]
          ▲          ▲          ▲             ▲
          └──── List 0 / List 1 ─┘             │
                     当前 B2                   │
                                               │
                     当前 P4 ──参考列表索引────┘
```

示意图只表达短期、长期图像都可能经列表被引用。实际 List 0/1 顺序按规范排序规则构造，也可由切片头重排；滑动窗口或 MMCO 决定图像何时不再作为参考。

## 4. HEVC / H.265：以 RPS 明确每图所需的参考集合

### 4.1 Reference Picture Set（RPS）

每张图像关联一个 RPS，列出当前图像和未来解码图像可能使用的参考图像。RPS 的核心优势是：解码器可以据此明确哪些图像还必须保留、哪些图像之后不再需要，而不必仅依赖“最旧图像先删”的滑动窗口策略。

HEVC 将 RPS 中的参考图像分成五组：

| 组 | 含义 | 是否用于当前图像预测 |
|---|---|---|
| `StCurrBefore` | POC 早于当前图像的短期参考 | 是 |
| `StCurrAfter` | POC 晚于当前图像的短期参考 | 是 |
| `StFoll` | 短期参考，但只为后续图像保留 | 否 |
| `LtCurr` | 长期参考，当前图像可用 | 是 |
| `LtFoll` | 长期参考，只为后续图像保留 | 否 |

这里的 Before/After 指图像顺序计数（POC）关系，不代表解码顺序。为了双向预测，POC 在当前图像之后的图像可能已经先解码并保存在 DPB。

### 4.2 RPS 的信令与 DPB 更新

- RPS 可在 SPS 中定义并由图像引用，也可以在 slice header 中显式给出；还支持基于先前 RPS 的差分预测信令。
- 当前图像的 RPS 同时描述“本图预测要用什么”和“哪些参考图像需为之后保留”。
- 不在当前 RPS 且不再被输出或其他约束需要的图像可从 DPB 移除。
- IDR、BLA、CRA 等 IRAP / 随机访问图像类型对允许的旧参考依赖和解码刷新行为有不同语义，不能都简化成同一种“清空 DPB”。

### 4.3 参考图像列表

HEVC 从 RPS 的当前参考组构造 L0、L1。默认顺序按短期 Before、短期 After、长期等规则建立，再可由 slice header 的列表修改语法调整。一个图像可以出现在两个列表里；B slice 常用双向预测，但具体是否使用两列表由 slice 类型及编码选择决定。

**RPS 是“图像级的参考集合/存留计划”；L0/L1 是“当前 slice 用来索引预测参考图像的列表”。** 两者相关但不是同一概念。

### HEVC：RPS 到参考列表

```text
当前图像 POC=8 的 RPS（例）

StCurrBefore: POC 4 ─┐
StCurrAfter:  POC 12 ├── 当前可用参考 ──▶ 构造 RefPicList0 / RefPicList1
LtCurr:       POC 0 ─┘
StFoll:       POC 16 ─── 只为之后图像保留，不用于当前图像
LtFoll:       POC 24 ─── 只为之后图像保留，不用于当前图像

当前图像的 RPS 同时告诉解码器：哪些图像需保留、哪些可移除。
```

Before/After 表示 POC 相对当前图像的位置，不表示解码先后；例如 POC 12 可能已先解码，供 POC 8 做预测。

## 5. AV1：8 个参考帧槽 + 显式刷新位图

### 5.1 槽不是 8 张互不重复的图像

AV1 有 **8 个参考帧槽**。槽保存已解码图像及相关元数据；多个槽可以指向同一帧缓冲，因此“8 个槽”不等于“必须同时保存 8 张不同图像”。

常见参考帧类型包括 `LAST`、`LAST2`、`LAST3`、`GOLDEN`、`BWDREF`、`ALTREF2`、`ALTREF`。块语法使用参考帧类型，而帧头中的索引映射将这些类型映射到实际参考槽。

### 5.2 Refresh frame flags

`refresh_frame_flags` 是 8 位位图，指定当前图像解码完成后要写入哪些槽。位为 1 的槽更新为当前帧；位为 0 的槽保持原有内容。关键帧通常刷新全部槽，其他帧可以只更新若干槽。`show_existing_frame` 还能直接显示某个既有槽中的帧，而无需再次解码其图像数据。

这是一种与 AVC 的逐图参考标记命令、HEVC 的 RPS 不同的接口：它直接指出**当前帧覆盖哪些槽**。编码器负责设计槽的复用计划。

### 5.3 参考槽映射、短信令和顺序提示

- 帧头为 `LAST`、`GOLDEN` 等参考类型给出槽索引，或使用 `frame_refs_short_signaling`，只显式提供部分槽索引，再由规范的 `set_frame_refs` 过程推导其他索引。
- 若启用 `order_hint`，槽还带有顺序提示，用于推导相对顺序、参考帧类型和相关工具信息。它不能简单等同于 HEVC 的完整 POC，也不能单独承担 DPB/RPS 的全部职责。
- 每个块可从当前映射中选择一个或两个参考帧类型；复合预测使用两套参考信息。AV1 没有 AVC/HEVC 那种按 P/B slice 来定义 L0/L1 的完全相同结构。

### AV1：类型映射到槽，刷新位图更新槽

```text
帧头参考类型映射                    8 个参考槽
LAST   ───────────────────────────▶ slot 0: F10
LAST2  ───────────────────────────▶ slot 1: F8
GOLDEN ───────────────────────────▶ slot 2: F4
ALTREF ──────────────────────────▶ slot 3: F12
                                    slot 4: F7
                                    slot 5: F6
                                    slot 6: F3
                                    slot 7: F0

当前帧 F13 解码后，假设刷新位图选中 slot 1 和 slot 3：
slot 1 ◀── F13      slot 3 ◀── F13      其他槽保持原内容
```

参考槽是索引入口，不一定各自保存不同帧。示意位图仅表示更新哪些槽，不展开语法位序。

## 6. 对照表

| 维度 | AVC / H.264 | HEVC / H.265 | AV1 |
|---|---|---|---|
| 缓冲抽象 | DPB | DPB | 解码帧缓冲池 + 8 个参考帧槽映射 |
| 管理核心 | 参考图像标记：滑动窗口或 MMCO | 每图 RPS 指定参考与保留集合 | `refresh_frame_flags` 指定更新槽 |
| 参考集合信令粒度 | 图像标记语法 + slice 参考列表 | picture/slice 的 RPS + 列表构造 | frame header 的槽映射和更新位图 |
| 短期/长期参考 | 明确区分，MMCO 可转换与管理 | RPS 明确分短期/长期当前及后续参考组 | 没有同样的短期/长期参考图像标记模型；使用槽名、映射和 order hint |
| 当前图像引用列表 | P: L0；B: L0/L1，可重排 | 从 RPS 构造 L0/L1，可修改 | LAST/GOLDEN 等类型映射到槽，块选择参考类型 |
| 刷新/随机访问 | IDR 清理参考依赖；普通 I 不必清理 | IDR/BLA/CRA 等 IRAP 类型分别定义刷新/随机访问语义 | KEY_FRAME 刷新参考槽；INTRA_ONLY 的行为不等同于关键帧全刷新 |
| 编码/显示顺序 | 可不同，DPB 管理输出重排和参考 | 可不同，RPS 以解码顺序管理存留，POC 描述图像顺序 | 可不同；order hint 辅助排序和参考推导，显示/解码模型另行描述 |

## 7. 设计演进：MMCO、RPS 与 AV1 参考槽

这些机制不是一条“旧机制全有缺陷、新机制全部解决”的直线。它们是在不同码流结构、随机访问需求和并行解码目标下作出的取舍。可以把演进概括为：**从操作式标记命令，转向每图声明所需集合，再转向固定槽位的引用与刷新映射。**

### 7.1 AVC MMCO 的负担与边界

H.264 的自适应参考图像标记使用 MMCO 命令，逐项改变 DPB 中图像的参考状态。这种方式功能强，但有几个实际负担：

- **状态式、命令式信令较复杂。** 解码器需要按顺序执行 MMCO，并维护短期图像编号、长期索引和当前 DPB 状态。编码器与解码器必须对每条命令保持一致理解。
- **参考标记和参考列表是两步。** MMCO 决定哪些图像留在 DPB、如何标记；slice 的参考列表构造/重排再决定当前预测使用哪个列表项。二者都要正确维护。
- **滑动窗口策略不够灵活。** 不发送自适应 MMCO 时，短期图像按窗口规则淘汰；若编码器想长期保留某张图像或精细安排未来用途，就需要额外命令。
- **错误恢复与随机访问依赖明确边界。** 丢失或误解析影响 DPB 状态的命令，可能使后续参考关系难以恢复；IDR 等刷新点因此很重要。

这不是说 MMCO 不能表达灵活策略，而是灵活性来自逐条状态操作，增加了语法、状态维护和实现验证成本。

### 7.2 HEVC RPS 的改进：表达“集合”，而非逐条改状态

HEVC 将当前图像的 Reference Picture Set（RPS）作为核心：列出当前图像可用、未来仍需保留，以及不再需要的参考图像集合。相较 AVC 的滑动窗口/MMCO 模式：

- 解码器能从当前图像的 RPS 推导哪些图像要保留、哪些可移除，参考管理更接近**声明期望状态**，减少单独的逐图 MMCO 式命令序列。
- RPS 同时支撑当前图像的引用集合和后续图像的保留计划，短期/长期、当前/后续用途都有结构化分类。
- RPS 可复用 SPS 中的集合，也可基于先前集合预测信令，降低重复描述成本。

代价是 RPS、POC 差值、短期/长期集合及列表构造规则本身较复杂；它并未消除参考列表重排，也未消除 DPB 和输出重排序管理。

### 7.3 AV1 槽位方案的改进方向

AV1 不沿用 H.264 的 MMCO 命令模型，也不直接使用 HEVC 的五组 RPS 结构。它将参考图像存储抽象成 **8 个参考帧槽**：帧头把 `LAST`、`GOLDEN`、`ALTREF` 等参考类型映射到槽，解码当前帧后用 `refresh_frame_flags` 指定要覆盖的槽。

相对于逐条 MMCO 状态操作，这种方案的特点是：

- **刷新动作可用一个位图表达。** 每位对应一个槽，便于解析“当前帧更新哪些参考入口”；不必逐条发送删除/转换/设置长期索引等操作序列。
- **参考类型与实际存储位置分层。** 块使用语义化的参考类型，帧头再映射到具体槽；槽位可以复用，多个槽也可指向同一帧，编码器能灵活安排长期、短期和未来参考角色。
- **支持快速显示既有帧。** `show_existing_frame` 可显示已存槽中的帧，不必重新传输完整图像样本。
- **短信令可推导部分映射。** `frame_refs_short_signaling` 和 `set_frame_refs` 可减少逐项传递引用映射的信息；启用时，`order_hint` 帮助推导参考顺序。

需要注意：AV1 的 8 槽不是“无限参考”或天然更简单的 DPB。编码器仍需管理槽的生命周期和复用；槽映射、order hint、刷新位图及解码显示模型也带来自己的规则。AV1 的主要变化是**管理接口和抽象方式不同**，并非直接消除所有参考管理复杂度。

### 7.4 对照：三种设计分别把复杂度放在哪里

```text
AVC：  DPB 状态 + 滑动窗口 / MMCO 命令 + 列表构造/重排
                   ↓ 改进为声明集合
HEVC： 每图 RPS（当前/后续、短期/长期）+ 列表构造
                   ↓ 改为槽位映射和位图刷新
AV1：  8 个可复用槽 + 参考类型映射 + refresh_frame_flags
```

| 设计问题 | AVC / MMCO | HEVC / RPS | AV1 / slots |
|---|---|---|---|
| 如何取消旧参考 | 滑动窗口或 MMCO 操作 | 当前 RPS 表达当前及后续需要的集合 | 新帧刷新选中的槽；未刷新槽保留 |
| 如何保留未来会用的帧 | MMCO 长期索引或编码器管理短期状态 | `StFoll` / `LtFoll` 等组表达后续用途 | 编码器把帧留在槽中，并通过映射继续引用 |
| 主要优势 | 机制成熟、策略灵活 | 集合表达清晰，DPB 更新和当前引用集合联系紧密 | 位图刷新直接，槽位可复用，引用类型映射灵活 |
| 主要复杂度 | 命令执行和 DPB 状态同步 | RPS 信令、POC 关系、列表构造 | 槽位生命周期、类型映射、刷新与顺序提示 |

因此，“AV1 针对 MMCO 缺陷的改进”应准确表述为：**AV1 没有继续采用逐条 MMCO 标记接口，而用固定槽位、引用类型映射和刷新位图组织参考管理，降低单次刷新操作的表达负担，并支持灵活复用槽位；它并不是 HEVC RPS 的简单升级版，也没有消除参考生命周期管理问题。**

## 8. 易混淆点

1. **参考帧数量不等于码流里可见的参考列表长度。** DPB 容量、长期保留图像、当前 slice 的列表长度和某个块实际可选的参考数是不同限制。
2. **参考帧与显示缓冲不是一回事。** 一张图像可能还要等待输出但已不再用于预测；也可能仍供预测但输出时间已处理。
3. **双向预测不表示必须有两张不同图像。** 列表项可能指向同一图像，规范和编码器也允许某些列表构造复用图像。
4. **“关键帧”不要跨标准直接等同。** AVC IDR、HEVC IDR/BLA/CRA、AV1 KEY_FRAME 的刷新和随机访问细节不同。
5. **编码器的 GOP/层级结构不是参考管理语法本身。** 编码器可用层级 B 帧、长期参考、AltRef 等策略；标准规定解码端如何解释其引用和刷新信令。
